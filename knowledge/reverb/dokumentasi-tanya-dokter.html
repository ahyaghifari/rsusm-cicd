Tanya Dokter — Chat Konsultasi Real-Time

Dokumentasi ini menjelaskan konsep dasar di balik fitur "Tanya Dokter" (Reverb, Echo, protokol Pusher, broadcasting, push notification, job queue) dan alur kerja end-to-end — mulai dari pasien membuat sesi konsultasi, dokter menerima & membalas, sampai notifikasi sampai ke pasien meski browser sudah ditutup.

Laravel Reverb Laravel Echo Livewire 3 Alpine.js Web Push (VAPID) Service Worker Queue Worker

1 Pendahuluan

Fitur "Tanya Dokter" memungkinkan pasien berbicara langsung dengan dokter lewat chat — tanpa perlu membuat akun. Pasien diberi tautan unik (/{rumahsakit}/konsultasi/{token}) yang menjadi "ruang chat" pribadinya.

Tantangan utamanya: chat harus terasa instan di kedua sisi (pasien ↔ dokter), dan pasien harus tetap diberi tahu ada balasan baru meskipun dia sedang membuka halaman lain, tab lain, atau bahkan sudah menutup browser-nya.

Untuk itu dipakai tiga blok bangunan utama:

🔌 Reverb Server WebSocket — jalur komunikasi instan dua arah
→terhubung lewat
📡 Echo Library JS di browser yang "mendengarkan" event dari Reverb
→jika browser tertutup
🔔 Web Push Notifikasi sistem operasi via Service Worker, tanpa browser aktif

2 HTTP vs WebSocket

Sebelum membahas Reverb, penting memahami kenapa cara kerja web "biasa" tidak cukup untuk chat real-time.

HTTP — "Kirim Surat"
Browser bertanya → Server menjawab → koneksi ditutup
Untuk tahu pesan baru, browser harus bertanya ulang berkali-kali (polling)
❌ Boros & terasa lambat untuk chat
WebSocket — "Telepon"
Koneksi dibuka sekali dan tetap terbuka selama dibutuhkan
Server bisa mendorong data ke browser kapan saja — tanpa diminta
✅ Pesan baru langsung sampai, instan

Broadcasting adalah pola di Laravel yang memanfaatkan WebSocket: server "memancarkan" sebuah event begitu sesuatu terjadi (mis. pesan baru terkirim), lalu semua browser yang sedang "berlangganan" topik terkait langsung menerimanya — tanpa refresh halaman.

3 Apa itu Laravel Reverb?

Reverb adalah server WebSocket buatan tim Laravel sendiri (terintegrasi penuh sejak Laravel 11/12). Tugasnya: menerima koneksi WebSocket dari banyak browser sekaligus, lalu meneruskan event dari aplikasi Laravel ke browser-browser yang relevan.

Kenapa penting Sebelum Reverb, developer Laravel umumnya memakai layanan pihak ketiga berbayar seperti Pusher (di-hosting orang lain). Reverb membuat kita bisa self-host sendiri — gratis, tanpa biaya bulanan, dan data tetap di server kita sendiri (penting untuk data layanan kesehatan yang sensitif).

Dijalankan sebagai proses long-running terpisah:

# development
php artisan reverb:start

# production — dijalankan sebagai daemon via Supervisor (lihat 08-production-reverb-queue-setup.md)
php artisan reverb:start --host=0.0.0.0 --port=8080

4 Lho, Kenapa Kata "Pusher" Masih Muncul?

Ini bagian yang sering membingungkan di awal — kita tidak memakai atau membayar layanan Pusher.

Reverb sengaja dibuat kompatibel dengan protokol Pusher — artinya Reverb "berbicara" dalam format pesan yang identik dengan layanan Pusher.

Analogi Pusher itu seperti "bahasa Inggris" yang sudah dipakai banyak orang, dan banyak "alat penerjemah" (pusher-js untuk browser, pusher/pusher-php-server untuk PHP) sudah dibuat untuk bahasa ini. Daripada membuat bahasa baru, Reverb memilih "berbicara bahasa yang sama" — sehingga semua alat yang sudah ada bisa langsung dipakai, cukup diarahkan ke server kita sendiri.

Jadi: "Pusher" di sini adalah nama protokol/format komunikasi, bukan layanan yang kita pakai. Konfigurasi BROADCAST_CONNECTION=reverb di .env memastikan semuanya 100% self-hosted.

5 Laravel Echo

Echo adalah library JavaScript di sisi browser yang membungkus pusher-js agar mudah dipakai dari konteks Laravel. Berkat Echo, kode untuk "mendengarkan" event jadi sangat sederhana: 

Echo.channel('konsultasi.<token>')
    .listen('PesanDikirim', (payload) => {
        // payload = data dari broadcastWith() di Laravel
        console.log('Pesan baru:', payload);
    });

Konfigurasi (resources/js/echo.js)

import Echo from 'laravel-echo';
import Pusher from 'pusher-js';

window.Pusher = Pusher;

window.Echo = new Echo({
    broadcaster: 'reverb',
    key: import.meta.env.VITE_REVERB_APP_KEY,
    wsHost: import.meta.env.VITE_REVERB_HOST,
    wsPort: import.meta.env.VITE_REVERB_PORT ?? 80,
    wssPort: import.meta.env.VITE_REVERB_PORT ?? 443,
    forceTLS: (import.meta.env.VITE_REVERB_SCHEME ?? 'https') === 'https',
    enabledTransports: ['ws', 'wss'],
    namespace: '',  // PENTING — lihat catatan di bawah
});
Jebakan: namespace: '' Secara default, Echo menambahkan prefiks App.Events. ke setiap nama event yang didengarkan. Tapi setiap event di project ini mendefinisikan broadcastAs() dengan nama pendek tanpa namespace ("SesiStatusBerubah", "PesanDikirim") — sehingga nama yang disiarkan server tidak pernah cocok dengan yang didengarkan Echo, dan listener Livewire diam selamanya tanpa error apa pun. Mengosongkan namespace membuat Echo mendengarkan nama event apa adanya. Detail lengkap penelusuran bug ini ada di 05-mismatch-namespace-echo-broadcastas.md.

window.Echo hanya tersedia di halaman yang me-load resources/js/app.js (yang meng-import ./echo) lewat @vite(...). Panel Filament dokter (/dokter) butuh render hook tambahan agar asetnya ikut dimuat — lihat 04-window-echo-hilang-di-panel-filament.md.

6 Channel: Public vs Private

Channel adalah "saluran" topik tertentu yang bisa di-subscribe oleh browser. Laravel punya tiga jenis:

JenisSiapa boleh subscribe?Perlu otorisasi di routes/channels.php?Dipakai untuk
Channel (publik) Siapa saja yang tahu nama channel-nya Tidak konsultasi.{token} — pasien (token UUID = "kunci"-nya)
PrivateChannel Hanya user terautentikasi yang lolos otorisasi Ya — closure konsultasi.dokter.{dokterId} — dashboard dokter
PresenceChannel Sama seperti private + daftar siapa saja yang online Ya (tidak dipakai di fitur ini)

Channel publik konsultasi.{token}

Pasien tidak punya akun, jadi PrivateChannel (yang mensyaratkan login) tidak bisa dipakai. Keamanannya bersandar pada nama channel itu sendiri: token adalah UUID v4 (122-bit acak, praktis mustahil ditebak — sama seperti link undangan Zoom/Google Meet). Siapa pun yang memegang token bisa subscribe, tapi untuk mendapatkan token, pasien harus melalui alur resmi (membuat sesi via halaman "Tanya Dokter").

Private channel konsultasi.dokter.{dokterId}

Channel ini menyiarkan "ada sesi baru / status berubah" untuk seorang dokter. Karena ID dokter berupa angka kecil yang mudah ditebak (1, 2, 3, ...), channel ini wajib diotorisasi — kalau publik, siapa pun bisa mengintip kapan ada pasien baru meminta konsultasi ke dokter tertentu. 

// routes/channels.php
Broadcast::channel('konsultasi.dokter.{dokterId}', function ($user, $dokterId) {
    return $user->bisaMenanganiDokter((int) $dokterId);
});

$user otomatis terisi dari sesi login Filament. Closure ini berjalan di server — kalau hasilnya false atau melempar exception, Reverb menolak permintaan subscribe dengan 403 Forbidden.

7 Event Broadcast

Event broadcast adalah event Laravel biasa yang juga "dipancarkan" ke Reverb agar diteruskan ke browser. Project ini punya dua event: PesanDikirim dan SesiStatusBerubah.

ShouldBroadcastNow vs ShouldBroadcast

InterfacePerilakuCocok untuk
ShouldBroadcast Masuk antrean (queue) dulu, baru dipancarkan Hal yang tidak mendesak (mis. notifikasi non-realtime)
ShouldBroadcastNow ✅ (dipakai di sini) Dipancarkan seketika, tanpa antrean Chat — harus terasa instan

Anatomi event: PesanDikirim

class PesanDikirim implements ShouldBroadcastNow
{
    use Dispatchable, InteractsWithSockets;

    public function __construct(
        public SesiKonsultasi $sesi,
        public KonsultasiPesan $pesan,
    ) {}

    // ① Ke channel mana event ini dikirim?
    public function broadcastOn(): array
    {
        return [new Channel('konsultasi.' . $this->sesi->token)];
    }

    // ② Nama event di sisi browser (tanpa ini → "App\Events\PesanDikirim")
    public function broadcastAs(): string
    {
        return 'PesanDikirim';
    }

    // ③ Apa isi "suratnya"? Tanpa ini, SELURUH model (+ relasi) ikut terkirim
    public function broadcastWith(): array
    {
        return [
            'id'         => $this->pesan->id,
            'pengirim'   => $this->pesan->pengirim->value,
            'isi'        => $this->pesan->isi,
            'created_at' => $this->pesan->created_at->toIso8601String(),
        ];
    }
}

Satu event, dua channel: SesiStatusBerubah

Event ini menyiarkan "status sesi berubah" (mis. MENUNGGU → BERLANGSUNG) dan dikirim ke dua channel sekaligus — satu untuk pasien, satu untuk dashboard dokter: 

public function broadcastOn(): array
{
    return [
        new Channel('konsultasi.' . $this->sesi->token),                  // ① halaman pasien (publik)
        new PrivateChannel('konsultasi.dokter.' . $this->sesi->dokter_id), // ② dashboard dokter (privat)
    ];
}

public function broadcastAs(): string { return 'SesiStatusBerubah'; }

public function broadcastWith(): array
{
    return [
        'sesi_id'     => $this->sesi->id,
        'token'       => $this->sesi->token,
        'status'      => $this->sesi->status->value,
        'mulai_at'    => $this->sesi->mulai_at?->toIso8601String(),
        'berakhir_at' => $this->sesi->berakhir_at?->toIso8601String(),
    ];
}

Mengirim event: broadcast(...) & ->toOthers()

broadcast(new PesanDikirim($this->sesi, $pesan))->toOthers();
Kenapa ->toOthers()? Tanpa ini, broadcast juga dikirim balik ke browser pengirim sendiri — pesannya akan muncul dua kali (sekali dari hasil aksi Livewire langsung, sekali lagi dari WebSocket). ->toOthers() memberi tahu Reverb: "kirim ke semua subscriber, kecuali koneksi yang memicu aksi ini".

8 Mendengarkan Event di Livewire

Bagian paling "ajaib": komponen Livewire bisa mendengarkan event broadcast langsung dari PHP, tanpa menulis JavaScript sama sekali — lewat atribut #[On('echo:...')].

Sisi pasien — KonsultasiChat (channel publik)

#[On('echo:konsultasi.{sesi.token},PesanDikirim')]
public function pesanMasuk(array $payload): void
{
    $this->riwayat[] = $payload; // → bubble chat baru muncul, tanpa reload
}

#[On('echo:konsultasi.{sesi.token},SesiStatusBerubah')]
public function statusBerubah(): void
{
    $this->sesi->refresh();

    if (in_array($this->sesi->status, [StatusSesiKonsultasi::SELESAI, StatusSesiKonsultasi::KEDALUWARSA])) {
        $this->dispatch('sesi-berakhir'); // → trigger cleanup di JS (lepas Echo channel, dll)
    }
}

Sisi dokter — KonsultasiDashboard (publik + privat sekaligus)

// ① Notifikasi real-time untuk SEMUA perubahan terkait dokter ini — private channel
#[On('echo-private:konsultasi.dokter.{dokter.id},SesiStatusBerubah')]
public function antreanBerubah(): void { /* re-render antrean */ }

// ② Pesan masuk untuk SESI YANG SEDANG DIBUKA — channel publik per-token, sama seperti pasien
#[On('echo:konsultasi.{sesiAktifToken},PesanDikirim')]
public function pesanMasuk(): void { /* ... */ }

#[On('echo:konsultasi.{sesiAktifToken},SesiStatusBerubah')]
public function sesiAktifBerubah(): void { /* ... */ }

Perhatikan awalan echo-private: — ini memberi tahu Echo "lakukan otorisasi dulu sebelum subscribe". Tanpa awalan ini, Echo akan mencoba subscribe sebagai channel publik dan gagal diam-diam (Reverb menolak di belakang layar, tanpa error yang terlihat).

Placeholder dinamis: {sesi.token} & {sesiAktifToken}

Livewire mengganti {nama.properti} di dalam string listener dengan nilai properti komponen yang sebenarnya — sebelum listener didaftarkan ke Echo. Hasilnya bisa dilihat langsung di "memo" Livewire saat halaman dimuat: 

// {sesi.token} sudah berubah jadi UUID asli sebelum dikirim ke browser:
"echo:konsultasi.b8b061f5-4792-4d6e-9412-d630da8470ab,PesanDikirim"
Jebakan: placeholder tidak boleh null Properti yang dipakai sebagai placeholder dinamis (mis. $sesiAktifToken) harus selalu bertipe string dengan default '' — bukan ?string $sesiAktifToken = null. Livewire memakai data_get() untuk mengisi placeholder, dan data_get() menganggap null sebagai "tidak ditemukan", lalu melempar: 
Unable to evaluate dynamic event name placeholder: {sesiAktifToken}

10 VAPID, Push Subscription & Service Worker

Lapisan 3 (Web Push) bekerja sangat berbeda dari WebSocket — server tidak menghubungi browser pasien secara langsung.

🌐 Browser PasienService Worker (sw.js)
→① subscribe()
☁️ Push Servicemilik Google/Mozilla/dst, BUKAN server kita
←④ kirim push
🖥️ Server Laravelqueue worker + minishlink/web-push
② endpoint dikirim & disimpan ke sesi_konsultasi.push_subscription  →  ③ saat dokter membalas, server POST ke endpoint tsb  →  ⑤ Push Service teruskan ke Service Worker → showNotification()

VAPID Keys — "surat kuasa" server ke Push Service

VAPID (Voluntary Application Server Identification) adalah sepasang kunci kriptografi (EC P-256) yang membuktikan push benar-benar berasal dari server kita: 

VAPID_PUBLIC_KEY   # dibagikan ke browser saat subscribe()
VAPID_PRIVATE_KEY  # rahasia di server, untuk menandatangani push — JANGAN commit ke git
VAPID_SUBJECT      # mailto: atau URL identitas pemilik server

Push Subscription

Hasil pushManager.subscribe() berupa objek JSON yang disimpan di kolom sesi_konsultasi.push_subscription: 

{
  "endpoint": "https://fcm.googleapis.com/fcm/send/APA91bHPRgkFLJu...",
  "keys": {
    "p256dh": "BEn7LbISGdbkc...",  // kunci publik enkripsi payload
    "auth":   "tBHItJI5svbpez7..." // secret autentikasi
  }
}

Service Worker (public/sw.js)

Service Worker adalah skrip JS yang berjalan terpisah dari halaman web — tetap aktif meski tab/browser ditutup. Dua event pentingnya: 

// Event "push" — Push Service mengirimkan data ke browser
self.addEventListener('push', (event) => {
    const data = event.data?.json() ?? {};
    event.waitUntil(
        self.registration.showNotification(data.title, {
            body:     data.body,
            icon:     '/img/favicon.png',
            tag:      'konsultasi-' + data.token,  // cegah notifikasi duplikat
            renotify: true,
            vibrate:  [200, 100, 200],
            data:     { url: data.url },
        })
    );
});

// Event "notificationclick" — pengguna klik notifikasi
self.addEventListener('notificationclick', (event) => {
    event.notification.close();
    const targetUrl = event.notification.data?.url ?? '/';
    event.waitUntil(
        clients.matchAll({ type: 'window', includeUncontrolled: true })
            .then((windowClients) => {
                // Fokuskan tab chat jika sudah terbuka, kalau belum buka tab baru
                for (const client of windowClients) {
                    if (client.url === targetUrl && 'focus' in client) return client.focus();
                }
                return clients.openWindow(targetUrl);
            })
    );
});

11 Job Queue & Worker

Mengirim Web Push butuh HTTP request ke Push Service yang bisa lambat (100–500ms) atau timeout. Kalau dilakukan langsung di kirimBalasan(), dokter harus menunggu setiap kali kirim pesan — pengalaman buruk. Solusinya: Job Queue.

1. kirimBalasan()Dokter klik "Kirim"
→
2. Response langsungDokter tidak menunggu
⇣dispatch()
3. Job masuk antreanSendWebPushNotification
→queue:work
4. Worker proses di backgroundHTTP POST ke Push Service
// app/Jobs/SendWebPushNotification.php
class SendWebPushNotification implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 2;

    public function __construct(
        private readonly int    $sesiId,
        private readonly string $title,
        private readonly string $body,
        private readonly string $url,
        private readonly string $token,
    ) {}

    public function handle(): void
    {
        $sesi = SesiKonsultasi::find($this->sesiId);
        if (! $sesi?->push_subscription) return;

        $webPush      = new WebPush(['VAPID' => [
            'subject'    => config('webpush.vapid.subject'),
            'publicKey'  => config('webpush.vapid.public_key'),
            'privateKey' => config('webpush.vapid.private_key'),
        ]]);
        $subscription = Subscription::create(json_decode($sesi->push_subscription, true));

        $webPush->queueNotification($subscription, json_encode([
            'title' => $this->title, 'body' => $this->body,
            'url'   => $this->url,   'token' => $this->token,
        ]));

        foreach ($webPush->flush() as $report) {
            // Subscription kadaluwarsa? bersihkan agar tidak dicoba lagi
            if ($report->isSubscriptionExpired()) {
                $sesi->update(['push_subscription' => null]);
            }
        }
    }
}

Dipanggil dari KonsultasiDashboard::kirimBalasan() setelah broadcast:

broadcast(new PesanDikirim($sesi, $pesan))->toOthers();

if ($sesi->push_subscription) {
    SendWebPushNotification::dispatch(
        $sesi->id,
        'Pesan dari ' . $this->dokter->nama,
        $pesan->isi,
        $chatUrl,
        $sesi->token,
    );
}
Wajib berjalan Tanpa php artisan queue:work berjalan, Lapisan 3 (Web Push) tidak akan pernah terkirim — job hanya akan menumpuk di antrean. Lapisan 1 & 2 tidak terpengaruh karena keduanya bekerja lewat WebSocket yang sudah tersambung, bukan lewat queue.

Dipancarkan seketika (ShouldBroadcastNow) ke channel publik konsultasi.{token}. Reverb meneruskan ke semua koneksi WebSocket yang sedang subscribe channel ini — termasuk dashboard dokter sendiri (yang juga "mendengarkan" sesi yang sedang dibuka).

Jika pasien punya push_subscription tersimpan

SendWebPushNotification::dispatch(...) — masuk antrean (untuk Lapisan 3, lihat di bawah).

Mulai dari sini, tergantung kondisi pasien:

📡 Reverb meneruskan event PesanDikirim via WebSocket ke channel konsultasi.{token}
LAPISAN 1+suara — Pasien di halaman lain (website sama)
  1. Alpine globalKonsultasiListener (terpasang di semua halaman lewat layout) menerima event lewat channel yang ia-subscribe dari localStorage.konsultasi_sesi.
  2. playNotificationSound() diputar (/audio/newmessage.mp3).
  3. isOnChat = false → toast "Pesan dari dr. X" muncul pojok kanan bawah, klik → buka halaman chat.
Bekerja selama tab website masih terbuka — tidak butuh queue.
LAPISAN 1+suara — Pasien sedang di halaman chat
  1. KonsultasiChat::pesanMasuk($payload) dipanggil via #[On('echo:konsultasi.{sesi.token},PesanDikirim')].
  2. $this->riwayat[] = $payload → Livewire re-render, bubble chat baru muncul + auto-scroll.
  3. globalKonsultasiListener tetap aktif (token tetap di localStorage meski di halaman chat) → playNotificationSound() tetap diputar.
isOnChat = true → toast tidak ditampilkan (pesan sudah terlihat langsung).
LAPISAN 2 — Pasien di tab lain (tab sama, tidak aktif)
  1. globalKonsultasiListener tetap menerima event (koneksi WebSocket tab tidak terputus hanya karena tidak fokus).
  2. document.hidden === true → new Notification('Pesan dari dr. X', {...}) — notifikasi sistem operasi muncul instan.
Berlaku bersamaan dengan Lapisan 1 (toast tetap dibuat, suara tetap diputar) — keduanya tidak saling eksklusif.
LAPISAN 3 — Browser pasien tertutup total
  1. Koneksi WebSocket otomatis terputus → Reverb tidak bisa menjangkau pasien sama sekali.
  2. queue:work memproses job SendWebPushNotification yang sudah di-dispatch di langkah 4.
  3. WebPush::queueNotification() → HTTP POST ke endpoint Push Service yang tersimpan di push_subscription.
  4. Push Service meneruskan ke Service Worker pasien (berjalan walau browser tertutup) → showNotification().
  5. Klik notifikasi → notificationclick di sw.js → fokus tab chat yang ada, atau buka tab baru.
Satu-satunya lapisan yang butuh php artisan queue:work berjalan.
Catatan Lapisan 1, 2, dan 3 tidak saling eksklusif — tergantung kondisi nyata pasien (tab fokus? halaman mana? browser terbuka?), satu atau lebih lapisan bisa aktif sekaligus untuk satu pesan yang sama. Tujuannya: pasien selalu tahu ada balasan baru, lewat kanal apa pun yang tersedia saat itu.

16 Alur 4 — Sesi Berakhir

Sesi punya batas waktu (durasi_menit), dihitung dari berakhir_at (waktu absolut, dihitung server — bukan "sisa detik" yang bisa "reset" saat refresh).

Timer berjalan di kedua sisi

Pasien: konsultasiTimer(berakhir_at) (Alpine) menghitung mundur setiap detik. Dokter: countdown inline di dashboard, berubah merah saat ≤ 60 detik.

Saat hitungan mencapai 0 — sisi dokter

$watch('r', ...) mendeteksi r === 0 → otomatis memanggil $wire.siapAkhiri() → form "kesimpulan/catatan konsultasi" langsung muncul, dokter tidak perlu klik apa pun untuk memulai proses penutupan.

Saat hitungan mencapai 0 — sisi pasien

habis = true → area chat & form input disembunyikan (x-show="!habis"), digantikan overlay "Waktu konsultasi telah habis — menunggu dokter menutup sesi dan memberikan catatan…".

Dokter mengisi kesimpulan & klik "Akhiri Sesi"

status = SELESAI, kesimpulan disimpan → broadcast(new SesiStatusBerubah($sesi)) dipancarkan lagi (atau otomatis jadi KEDALUWARSA jika tidak direspons sama sekali).

Pasien: statusBerubah() menerima status SELESAI/KEDALUWARSA

dispatch('sesi-berakhir') → di JS: localStorage.removeItem('konsultasi_sesi'), Echo channel di-leaveChannel(). Halaman beralih ke mode transkrip baca-saja + menampilkan "Catatan dari dr. X" (kolom kesimpulan).

17 Glosarium

WebSocket
Jenis koneksi dua arah yang tetap terbuka, memungkinkan server "mendorong" data ke browser kapan saja tanpa diminta.
Reverb
Server WebSocket self-hosted milik Laravel, menggantikan kebutuhan layanan pihak ketiga seperti Pusher.
Protokol Pusher
Format pesan yang dipakai Reverb agar kompatibel dengan tooling Pusher yang sudah luas dipakai (pusher-js, Echo) — bukan berarti memakai layanan Pusher.
Laravel Echo
Library JS di browser untuk subscribe channel & mendengarkan event dari Reverb dengan API sederhana (Echo.channel(...).listen(...)).
Channel
"Saluran" topik yang bisa di-subscribe. Publik (Channel) — siapa saja bisa subscribe; Privat (PrivateChannel) — wajib login & lolos otorisasi di routes/channels.php.
Event Broadcast
Event Laravel yang juga dipancarkan ke Reverb. Didefinisikan lewat broadcastOn() (channel tujuan), broadcastAs() (nama pendek di browser), broadcastWith() (data yang dikirim).
ShouldBroadcastNow
Interface yang membuat event dipancarkan seketika (sinkron), tanpa antre di queue — dipakai untuk chat agar terasa instan.
broadcast(...)->toOthers()
Mengirim event ke semua subscriber channel kecuali koneksi pengirim sendiri — mencegah pesan muncul dobel di sisi pengirim.
#[On('echo:channel,Event')]
Atribut Livewire untuk mendengarkan event broadcast pada channel publik, memanggil method PHP saat event diterima — tanpa JS manual.
echo-private:
Varian awalan untuk channel privat — Echo akan melakukan proses otorisasi (request ke /broadcasting/auth) sebelum subscribe.
Placeholder dinamis {properti}
Bagian dari nama channel di #[On(...)] yang diganti Livewire dengan nilai properti komponen sebelum didaftarkan ke Echo. Properti ini wajib bertipe non-nullable.
VAPID
Sepasang kunci kriptografi (public/private) yang membuktikan ke Push Service bahwa Web Push berasal dari server kita yang sah.
Push Subscription
Objek (endpoint + kunci enkripsi) yang didapat browser dari Push Service saat pushManager.subscribe() — "alamat pengiriman" unik milik browser tsb.
Service Worker
Skrip JS yang berjalan di latar belakang, terpisah dari halaman web — tetap aktif menerima push event & menampilkan notifikasi meski browser/tab tertutup.
Push Service
Server perantara milik pembuat browser (FCM untuk Chrome, dll) yang menerima push dari server kita dan meneruskannya ke Service Worker browser pengguna — bahkan saat browser tertutup.
Job Queue / Worker
Mekanisme Laravel untuk menjalankan tugas (mis. kirim Web Push) di latar belakang lewat php artisan queue:work, agar tidak memblokir respons ke pengguna.
wire:key
Atribut Livewire yang memberi "identitas" pada elemen DOM untuk membantu morphdom — saat key berubah antar render, elemen lama dihapus & elemen baru disisipkan utuh (memastikan x-data Alpine ter-inisialisasi ulang dengan benar).
Bagian dari dokumentasi fitur "Tanya Dokter — Konsultasi Chat Real-Time". Lihat juga catatan teknis kronologis di reverb/README.md untuk detail setiap bug & perbaikan yang ditemukan selama pengembangan.
